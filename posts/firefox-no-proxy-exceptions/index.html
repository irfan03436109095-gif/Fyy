Firefox 已填代理，部分网站为何仍直连？检查代理例外

风2026-10-07— 次阅读
客户端与工具

Firefox 中填写了代理地址和端口，并不表示每个网站请求都会使用这个代理。连接设置里的例外列表，可能有意让一部分主机绕过浏览器代理。

本文处理 Firefox 自身的代理选择。若电脑同时启用 TUN、企业网络接管或其他 VPN，浏览器“不使用代理”的请求仍可能被其他层接管，不能仅凭一个设置断言最终出口。

示意图：浏览器代理例外影响这一层的选择，最终路径还要结合其他网络接管检查。

“不使用代理”具体是什么

Mozilla 官方连接设置说明把 No Proxy For 定义为不经代理的主机名或 IP 地址列表，并说明 <local> 可用于没有句点的简单主机名。它是连接选择条件，不是网页广告过滤器。

先确认你选用的是手动代理、系统代理、自动检测还是 PAC。不同来源需要检查相应配置，不能看到手动代理栏有旧地址，就认定当前正在使用它。官方说明还指出，连接设置会显示控制网络连接的扩展。

按四步找出一个目标的例外

  1. 记录问题页面的主机名。 只记域名及时间，不复制带账号令牌的完整 URL。登录页跳到另一个域名时，将两个主机名分别记录。
  2. 进入当前连接设置。 在 Firefox 设置中搜索“代理”或“连接设置”，按当前版本找到代理配置窗口；界面位置可能变化，可对照文末官方文档。
  3. 私下保存现有配置。 记录代理来源、端口、例外列表以及是否由扩展控制。公开求助时遮盖内部域名、账号和其他敏感项。
  4. 只核对相关例外。 对照目标主机名与现有条目。若列表含单位内网或本机访问要求，保留它们；不要把整个列表清空作为第一步。

如果你不确定一个条目的匹配范围，先查看客户端或浏览器的当前官方说明。不要把“不使用代理”的写法直接当成 PAC 语法，也不要套用另一个客户端的域名规则。

怎样证明改动实际生效

仅在你能确认用途的情况下，暂时移除与目标相关的一个误加条目，保存后重新发起目标请求。保持节点、客户端模式、其他扩展和目标任务不变。

同时查看本地代理客户端提供的连接记录：有没有出现这次目标请求、采用什么规则、选择什么节点。日志没有出现也可能是日志级别或观察方式不完整，应记录为“未观察到”，继续核对，而不是直接认定直连。

对照项 修改前 修改后
当前代理来源 自行填写 应保持一致
相关例外条目 自行填写 只改变该项
客户端中的目标连接记录 有／无／无法观察 有／无／无法观察
原页面或登录任务 成功／失败及提示 成功／失败及提示

如果改动无效，恢复原条目，再查 PAC、扩展、客户端分流或目标服务。不要连续改动多套设置，让前后条件无法比较。

验收时还要检查本地访问

目标网站恢复之后，检查原本需要直连的本地页面或单位内网是否仍可使用。机场推荐中的客户端教程，应该帮助你明确每个请求由哪处配置决定，而不是要求所有目标无差别走代理。
