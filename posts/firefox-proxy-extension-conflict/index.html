Firefox 代理设置总被改回？检查连接设置与扩展控制

王牌飞行员2026-09-28— 次阅读
客户端与工具

Firefox 里刚选好“使用系统代理设置”，重启后却又变成手动代理，或者只有 Firefox 反复弹出代理认证窗口，常见原因是浏览器连接设置、代理扩展与机场客户端同时在控制出站路径。

先记录当前连接方式

打开 Firefox 设置，搜索“网络设置”，进入“连接设置”。Mozilla 官方说明，这里可以选择不使用代理、自动检测、使用系统代理、手动代理或自动代理配置 URL；页面也会显示控制连接方式的扩展。

先截图或记录以下内容：

  1. 当前选择的是哪一种连接方式。
  2. 手动代理的主机、端口和“不使用代理”列表是否有旧值。
  3. 是否填写了 PAC 自动配置地址。
  4. 页面是否提示某个扩展正在控制连接。

不要把订阅地址、账号或完整代理凭据放进截图。

一次只保留一个控制来源

如果机场客户端已经接管 Windows 系统代理，Firefox 可先临时改为“使用系统代理设置”，完全退出浏览器后重新打开，再访问固定测试页。若恢复正常，说明原来的手动值或 PAC 配置与客户端路径不一致。

如果页面提示扩展控制连接，先记住扩展名称，只对与代理相关的扩展做临时停用对照。Mozilla 的连接设置文档明确提到，可以在该页面停用控制连接的扩展。停用后重启 Firefox；若问题消失，再决定保留客户端还是扩展，不要让两者同时反复改设置。

认证窗口怎么判断

反复要求用户名和密码，说明 Firefox 实际连接到了一个要求认证的代理，但不等于机场账户密码错误。先核对代理地址和端口是否仍指向本机客户端；如果是公司或校园代理，应遵循管理员配置，不要自行绕过。

若选“无代理”后直连正常，而“使用系统代理”失败，继续检查机场客户端和系统代理。若所有模式都只在一个网站失败，应检查目标网站、DNS 或分流规则。

验收方法

最终只保留一个明确的代理控制来源。重启 Firefox 和机场客户端后，核对连接设置没有再次变化；测试普通网页、需要登录的网站和下载任务；关闭客户端后也应能按预期恢复直连。这样才能区分浏览器设置冲突与节点故障。

来源：Mozilla：Firefox 连接设置。
