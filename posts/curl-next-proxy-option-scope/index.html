一条 curl 命令发两次请求，第二次没走代理？检查 --next 的作用域

风2026-11-28— 次阅读
客户端与工具

为了同时验收两个公开页面，把两组 curl 参数写进一条命令后，常见漏项是只在第一组写了 --proxy。遇到一组能访问、另一组表现不同，先把命令按 --next 拆开读。

示意图。把显式代理配置写在每段操作内，分别核对两个请求。

每经过一个 --next，重新看这一段的选项

--next 开启下一段操作，局部选项会重置。--proxy、--output 和 --write-out 都要按该段用途重新指定。官方手册把 --fail-early 列为全局选项，可以让检查遇到传输错误时及早停止。只在同一段内连续列出 URL 时，局部选项继续适用于该操作。

用两条普通网页请求做对照

下面是 Windows PowerShell 示例。先在机场客户端确认本机 HTTP 或混合代理端口，再替换示例端口。测试地址使用无登录网页，两段各打印一行结果。proxy_used 需要 curl 8.7.0 或更新版，可用 curl.exe --version 查看。

$localProxy = 'http://127.0.0.1:7890'
curl.exe -q --fail-early `
  --silent --show-error --proxy "$localProxy" --output NUL `
  --write-out 'a %{response_code} proxy=%{proxy_used}\n' 'https://example.com/' `
  --next `
  --silent --show-error --proxy "$localProxy" --output NUL `
  --write-out 'b %{response_code} proxy=%{proxy_used}\n' 'https://example.org/'

把代理选择和网站响应分别验收

  • 两行都为 proxy=1，说明 curl 为两次传输都使用了代理。若其中一个仍返回异常状态，再核对该网站和客户端连接记录。
  • 一行是 proxy=0 时，查那一段是否缺少 --proxy，也查是否命中本机 NO_PROXY 例外。没有显式参数时，环境里的代理仍可能生效。
  • 旧版缺少 proxy_used 时，可拆成两条命令逐一执行，并在客户端连接记录里按时间和测试域名核对。记录目标域名和 HTTP 状态即可，避免截取订阅或认证字段。

原命令中的两次传输都能按预期使用代理之后，再用同样的分段写法替换成自己的合法目标。
