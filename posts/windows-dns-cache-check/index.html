切换机场节点后仍解析到旧地址？先检查 Windows DNS 缓存

切换机场节点后，网页仍访问旧服务器，很多人会立刻重装客户端或反复换节点。更稳妥的做法是先分层判断：域名解析结果是否缓存、浏览器是否复用旧连接、代理客户端是否自己接管 DNS。Windows 的 DNS 客户端缓存只是其中一层，清空它并不能解决所有代理问题。

第一步：只读查看缓存

打开命令提示符，执行：

ipconfig /displaydns

在输出中查找目标域名。如果能看到记录，记下记录类型和剩余生存时间。没有记录也不代表没有缓存，因为浏览器或机场客户端可能维护自己的解析结果。

接着用系统解析命令做一次对照：

Resolve-DnsName example.com

把 example.com 换成出现问题的公开域名。不要用机场订阅链接测试，也不要把订阅参数贴进截图或日志。

第二步：仅在证据指向系统缓存时清理

如果系统缓存中的地址明显过期，先关闭正在访问该站的浏览器标签页，再执行：

ipconfig /flushdns

重新运行 /displaydns，然后打开一个新的浏览器窗口复测。微软把 /flushdns 定义为刷新并重置 DNS 客户端解析器缓存；它不会修改机场订阅、节点规则或代理端口。

第三步：判断是否属于其他层

  • 系统解析已更新，但浏览器仍旧。 完全退出浏览器后重开，避免复用既有连接。
  • 直连解析和代理内解析不同。 检查客户端的 DNS 模式、分流规则及日志，不要盲目修改系统 DNS。
  • 只有一个节点异常。 保持其他条件不变，换到同地区另一个节点复测。
  • 所有节点都异常。 暂停代理后测试直连，确认本地网络是否本身存在解析故障。

验收方法

准备一个固定公开网页，按“清理前、清理后、换节点后”各访问一次，并记录系统解析结果、客户端日志时间和网页实际表现。如果只有清缓存后短暂恢复，很可能还有浏览器连接复用、代理 DNS 或上游解析问题，需要继续沿层级排查。

风悠悠的客户端排障原则是一次只改一个变量。机场推荐文章里常见的“换 DNS 就好”并不适用于所有情况；先用只读命令确认，再做可回退的最小修改，能避免把简单缓存问题扩大成配置故障。

微软官方 ipconfig 文档列出了 /displaydns 与 /flushdns 的用途和适用系统：ipconfig 命令文档。
