Firefox 单独打不开网站？检查 DoH 与代理 DNS 路径

同一台电脑上，其他浏览器通过机场客户端能打开网站，Firefox 却提示找不到服务器，问题不一定在节点。Firefox 可以使用 DNS over HTTPS（DoH）把域名查询发送到 HTTPS 解析服务；这条路径可能和系统 DNS、代理客户端的 DNS 接管方式不同。

DoH 是隐私功能，不应看到故障就永久关闭。正确做法是先记录当前设置，再用一次可回退的对照判断 DNS 路径是否相关。

先完成四项只读检查

  1. 在 Firefox 打开 设置 → 隐私与安全 → DNS over HTTPS，记录当前保护级别与提供商。
  2. 记录机场客户端使用的是系统代理、TUN 还是其他接管方式。
  3. 用同一域名比较 Firefox、另一个浏览器和直连状态。
  4. 查看客户端日志中是否出现该域名或对应连接，注意脱敏订阅地址。

Mozilla 说明，DoH 会通过加密 HTTPS 连接查询域名，并可能绕过本地 DNS 解析器。Firefox 也提供不同保护级别和回退行为，因此不能只凭“开着 DoH”判断一定绕过代理。

做一次临时对照

保持节点、网络和目标域名不变，只临时调整 Firefox 的 DoH 保护级别，然后完全关闭相关标签页并重新访问。记录：

  • 错误是否从 DNS 失败变为正常连接；
  • 机场客户端日志是否出现新的解析或连接记录；
  • 其他浏览器是否仍保持原结果。

对照完成后恢复原设置。如果关闭 DoH 后恢复，只能说明问题与 DNS 路径有关，下一步仍要核对客户端 DNS 模式、系统解析器和网络策略。不要把关闭隐私功能当成最终修复。

常见误判

  • 只有一个网站失败：目标域名、网站或分流规则也可能有问题。
  • Firefox 能开、其他浏览器不能开：不代表 DoH 一定更快，可能只是解析路径不同。
  • 换节点后恢复：也可能是旧连接或缓存同时被重建。
  • 企业或校园网络：本地 DNS 可能承担过滤或内部域名解析，应遵循网络管理员要求。

验收方法

最终设置应同时满足：常用域名可稳定解析、客户端分流符合预期、浏览器重启后仍正常、没有泄露订阅或账户信息。风悠悠的客户端排障建议一次只改一个变量，并保留恢复路径。

来源：Mozilla Firefox DNS over HTTPS 说明、Mozilla 的 DoH 网络配置说明。
